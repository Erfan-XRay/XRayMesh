مشکلتان را در فهرست زیر پیدا کنید. بیشتر راه‌حل‌ها با همین دو دستور روی سرور مشکل‌دار شروع می‌شوند.

## از اینجا شروع کنید

```bash
sudo xraymesh self-test
```

`self-test` برنامه‌های نصب‌شده، دسترسی فایل‌های تنظیمات و همهٔ سرویس‌ها را بررسی می‌کند: مش، پنل
وب، هر موتور تونل و سرور تست سرعت. هر چیزی که مشکل داشته باشد را گزارش می‌دهد.

برای مشکل‌های اتصال، منو را با `sudo xraymesh` باز کنید و **Connection diagnostics** را انتخاب
کنید. نشان می‌دهد پورت مش در حال گوش دادن هست یا نه، EasyTier کدام همتاها را می‌بیند و آخرین پیام‌های
اتصال چه بوده‌اند، به‌همراه راهنمایی مخصوص پروتکل شما.

وقتی جزئیات بیشتری لازم دارید، لاگ‌ها را ببینید:

| دستور | چه چیزی را نشان می‌دهد |
| :--- | :--- |
| `xraymesh logs` | مش و پنل وب، به‌صورت زنده. |
| `journalctl -u 'xraymesh-icmp@*' -n 30` | لینک‌های ICMP و PCK. |
| `journalctl -u xraymesh-updater-temp` | آخرین به‌روزرسانی‌ای که از پنل شروع شده. |

## پنل باز نمی‌شود

<Steps>

1. **سرویس روشن است؟** خروجی `sudo xraymesh self-test` باید **Web Dashboard service is active** را
   نشان دهد. اگر نه، `sudo xraymesh restart` را اجرا کنید.

2. **پورت باز است؟** پنل، اگر عوضش نکرده باشید، از پورت TCP ‏`11080` استفاده می‌کند. آن را در فایروال
   سرویس‌دهنده، و اگر از UFW استفاده می‌کنید در آن هم، باز کنید. `sudo xraymesh status` نشانی پنل
   را نشان می‌دهد.

3. **تونلی پورت پنل را گرفته؟** اگر تونلی روی همان پورت پنل ساخته‌اید، همهٔ تونل‌ها را متوقف کنید و
   بعد آن تونل را در پنل اصلاح یا حذف کنید:

   ```bash
   sudo xraymesh tunnels-stop
   ```

   وقتی درست شد، `sudo xraymesh tunnels-apply` بقیهٔ تونل‌ها را دوباره راه می‌اندازد.

4. **خطای HTTPS؟** دامنه باید همچنان به این سرور اشاره کند. برای گواهی تازه دوباره
   `sudo xraymesh ssl` را اجرا کنید، یا با `sudo xraymesh remove-ssl` به HTTP برگردید.

</Steps>

## نمی‌توانم وارد پنل شوم

- **لینک ورود کار نمی‌کند.** هر لینک فقط یک بار و تا ۶۰ دقیقه کار می‌کند. با
  `sudo xraymesh token` لینک تازه بگیرید.
- **تلاش‌های زیاد.** بعد از ۵ رمز اشتباه در یک دقیقه، ورود از آی‌پی شما تا پایان همان دقیقه مسدود
  می‌شود.
- **رمز را فراموش کرده‌ام.** با لینک ورود وارد شوید، یا با `sudo xraymesh password` رمز تازه بگذارید.
- **بعد از به‌روزرسانی از پنل خارج شدم.** وقتی پنل ری‌استارت می‌شود این طبیعی است. دوباره وارد شوید.

## سروری در بخش سرورها دیده نمی‌شود

این موارد را روی **هر دو** سرور بررسی کنید.

1. **نام و رمز شبکهٔ یکسان.** پیوستن با کد دعوت هر دو را تنظیم می‌کند. اگر آن‌ها را دستی وارد
   کرده‌اید، در <UiPath items={['نود', 'تنظیمات']} /> مقایسه‌شان کنید.

2. **پورت مش باز است.** پورت شنود (پیش‌فرض `11010`) را روی سروری که بقیه به آن وصل می‌شوند، در
   فایروال سرویس‌دهنده باز کنید:

   | پروتکل | چه چیزی را باز کنید |
   | :--- | :--- |
   | `dual`، `udp`، `tcp`، `ws`، `faketcp` | TCP و UDP |
   | `wss` | TCP |
   | `quic` | UDP |
   | `icmp` | پینگ (ICMP) باید به سرور اصلی برسد |
   | `pck` | پورت TCP لینک (`20000` تا `32767`) که کنار کد دعوت نشان داده می‌شود |

3. **نشانی درست در کد دعوت.** اگر پنل گفت آی‌پی عمومی شناسایی نشد، نشانی را در
   <UiPath items={['نود', 'همتاها و دعوت']} /> تنظیم کنید و کد را دوباره بسازید.

4. **شبکه پروتکل را عبور می‌دهد.** اگر پورت باز است و سرورها باز هم همدیگر را نمی‌بینند، ممکن است
   مسیر آن پروتکل را مسدود کند. پروتکل دیگری را امتحان کنید.
   [پروتکل‌های انتقال مش](../guides/transports/) را ببینید.

5. **در ICMP یا PCK، هر کد برای یک سرور.** کدی که یک سرور را وصل کرده، سرور دیگری را وصل نمی‌کند.
   روی سرور اصلی **کد تازه** را بزنید.

## تنظیماتم خودبه‌خود برگشت

این کار پشتیبان ایمنی است. بعد از تغییر پروتکل یا تنظیمات مشترک، سروری که تا **۹۰ ثانیه** هیچ
همتای وصل‌شده‌ای نداشته باشد، تنظیمات قبلی‌اش را برمی‌گرداند تا جدا نماند. معمولاً یعنی پروتکل تازه
بین سرورهایتان مسدود است؛ پروتکل دیگری انتخاب کنید. [SafeSync](../guides/safesync/) را ببینید.

## تونل کار نمی‌کند

<Steps>

1. **اجرا شدنش را بررسی کنید.** `xraymesh tunnels` همهٔ تونل‌های ذخیره‌شده را با پورت‌ها و وضعیت
   سرویسشان نشان می‌دهد.

2. **پورت‌های تونل را باز کنید**؛ در فایروال سرویس‌دهندهٔ سروری که تونل **روی آن اجرا** می‌شود.

3. **پروتکل را درست انتخاب کنید.** HAProxy فقط TCP را فوروارد می‌کند. برای سرویس‌های UDP مثل
   Hysteria2، WireGuard یا QUIC از Realm، GOST یا iptables با UDP یا TCP + UDP استفاده کنید.

4. **مقصد را بررسی کنید.** سرویس باید روی پورت سرور مقصد در حال گوش دادن باشد و آن سرور باید در
   بخش **سرورها** دیده شود. برای بررسی مسیر، از سرور تونل به مقصد **پینگ** بگیرید.
   [پینگ و تست سرعت](../guides/ping-speedtest/) را ببینید.

5. **تداخل پورت.** یک پورت را نمی‌شود هم‌زمان در دو تونل، یا در یک تونل و برنامهٔ دیگری روی همان
   سرور، استفاده کرد. در این حالت ساخت تونل با پیامی که پورت اشغال‌شده را نام می‌برد شکست می‌خورد.

</Steps>

## سروری برچسب خطا دارد

در بخش **تونل‌ها**، هر سروری که در نما هست یک وضعیت دارد:

| برچسب | معنی | راه‌حل |
| :--- | :--- | :--- |
| **در دسترس نیست** یا **پاسخ نداد** | این پنل از راه مش به آن سرور نرسید. | بررسی کنید روشن باشد و در بخش **سرورها** دیده شود. |
| **رمز شبکه نادرست** | رمز شبکهٔ آن سرور فرق دارد. | آن را با یک کد دعوت تازه دوباره به مش وصل کنید. |
| **نیازمند به‌روزرسانی** | نسخهٔ آن سرور برای این کار قدیمی است. | از ترمینال خودش با `sudo xraymesh update` به‌روزش کنید. |
| **نسخهٔ ذخیره‌شده** | آخرین تونل‌های شناخته‌شده‌اش را می‌بینید. | وقتی دوباره وصل شود، ویرایش باز می‌شود. |

## به‌روزرسانی شکست خورد

اگر به‌روزرسانی شکست بخورد، سرور خودش نسخهٔ قبلی را برمی‌گرداند و پنل هم این را اعلام می‌کند. برای
دیدن علت، روی آن سرور `journalctl -u xraymesh-updater-temp` را اجرا کنید. همیشه می‌توانید از ترمینال
هم به‌روزرسانی کنید:

```bash
sudo xraymesh update
```

## هنوز حل نشده؟

در [GitHub](https://github.com/Erfan-XRay/XRayMesh/issues) یک issue باز کنید و این‌ها را بنویسید:

- خروجی `sudo xraymesh self-test` و `xraymesh version`،
- پروتکلی که استفاده می‌کنید و محل میزبانی هر سرور (مثلاً ایران یا خارج)،
- انتظارتان چه بود و چه اتفاقی افتاد.

:::caution
پیش از فرستادن، کدهای دعوت، رمز شبکه، لینک‌های ورود و رمزهای عبور را از متن حذف کنید.
:::

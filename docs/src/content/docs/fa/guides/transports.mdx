پروتکل انتقال مشخص می‌کند ترافیک مش چطور بین سرورها جابه‌جا شود. همهٔ سرورهای یک مش از یک پروتکل
استفاده می‌کنند و کد دعوت آن را به سرورهای تازه می‌رساند. پروتکل را هنگام
[ساخت مش](../../start/create-mesh/) انتخاب می‌کنید و بعداً هم می‌توانید آن را از
<UiPath items={['نود', 'تنظیمات']} /> تغییر دهید.

## کدام را انتخاب کنم

| اگر… | انتخاب کنید |
| :--- | :--- |
| مطمئن نیستید | `dual` (پیش‌فرض) |
| UDP بین سرورهایتان خوب کار می‌کند | `udp` |
| UDP مسدود یا محدود شده | `tcp`، یا `faketcp` تا سرعت UDP را نگه دارید |
| اتصال‌های معمولی با بازرسی عمیق بسته (DPI) قطع می‌شوند | `ws`، یا اگر دامنه دارید `wss` |
| لینک پراتلاف است یا دیر به حالت عادی برمی‌گردد | `quic`، یا **مقاومت در برابر اتلاف بسته (KCP)** را روشن کنید |
| تقریباً هیچ چیز رد نمی‌شود، اما پینگ رد می‌شود | `icmp` |
| TCP وصل می‌شود، ولی بعد گیر می‌کند، قطع می‌شود یا کند می‌شود | `pck` |

## همهٔ پروتکل‌ها

| پروتکل | چطور کار می‌کند |
| :--- | :--- |
| `dual` | هم روی TCP و هم روی UDP گوش می‌دهد و مسیر سریع‌تر را خودکار انتخاب می‌کند. |
| `udp` | کمترین تأخیر. UDP باید روی همهٔ سرورها باز باشد. اگر سرویس‌دهندهٔ اینترنت UDP را ببندد، نگهبان ایمنی خودش به `dual` برمی‌گردد. |
| `tcp` | برای شبکه‌هایی که UDP در آن‌ها مسدود یا محدود است. |
| `ws` | ترافیک را در قالب WebSocket می‌پیچد تا از DPI رد شود. به گواهی نیاز ندارد. |
| `wss` | WebSocket روی TLS. به دامنه‌ای با گواهی معتبر نیاز دارد. |
| `quic` | QUIC با کنترل ازدحام BBR و بازگشت خودکار به TCP. |
| `faketcp` | UDP را شبیه TCP نشان می‌دهد تا محدودسازی UDP سرویس‌دهنده دور زده شود. لینک فقط به همتاهایی ساخته می‌شود که اضافه می‌کنید و سرورهای دیگر می‌توانند از راه آن‌ها به هم برسند. فقط IPv4. |
| `icmp` | مش را داخل بسته‌های پینگ و با کمک BackPack جابه‌جا می‌کند. کندتر از UDP است و محدودیت نرخ ICMP رویش اثر دارد. فقط IPv4. |
| `pck` | مش را داخل بسته‌های TCP که بدون پشتهٔ TCP هسته ساخته می‌شوند و با کمک BackPack جابه‌جا می‌کند. فقط IPv4. |

## ICMP و PCK

این دو پروتکل از [BackPack](https://github.com/AminMGMT/BackPack)، ساختهٔ امین محمدی، می‌آیند.
XRayMesh نسخهٔ رسمی آن را دانلود می‌کند، با checksumهای منتشرشده بررسی می‌کند و بدون تغییر اجرا
می‌کند. BackPack یک لینک رمزنگاری‌شده بین دو سرور می‌سازد و مش روی همان لینک اجرا می‌شود. روش کار
این دو کمی با بقیه فرق دارد:

- **یک سرور اصلی.** `icmp` یا `pck` را روی سرور اصلی، معمولاً سرور خارج، انتخاب کنید. همهٔ
  سرورهای دیگر با کدی از همین سرور وصل می‌شوند.
- **هر کد برای یک سرور.** هر کد دعوت فقط یک سرور را وصل می‌کند. بعد از پیوستن آن، برای سرور بعدی
  **کد تازه** را بزنید. [افزودن سرورها](../../start/add-servers/) را ببینید.
- **PCK به یک پورت TCP نیاز دارد.** هر لینک PCK روی سرور اصلی یک پورت TCP جداگانه بین `20000` و
  `32767` باز می‌کند. آن را در فایروال سرویس‌دهنده باز کنید.
- **MTU.** پیش‌فرض MTU برای ICMP به‌جای `1360`، عدد `1280` است.
- **رمزنگاری.** BackPack هر لینک را رمزنگاری می‌کند، اما سرورهایی که از راه لینک پیوسته‌اند
  مستقیم و با UDP ساده هم به هم می‌رسند. رمزنگاری مش را فقط وقتی برای صرفه‌جویی در CPU خاموش
  کنید که مش تنها دو سرور داشته باشد.

وضعیت لینک‌ها را در ترمینال ببینید:

- `xraymesh link-list` لینک‌ها و شمارندهٔ بسته‌هایشان را نشان می‌دهد.
- `xraymesh link-delete out-1234` یک لینک را حذف می‌کند.

:::note[آزمایشی]
ICMP و PCK آزمایشی هستند. وقتی سراغشان بروید که پروتکل‌های دیگر رد نمی‌شوند.
:::

## تغییر پروتکل

<Steps>

1. روی هر کدام از سرورها، <UiPath items={['نود', 'تنظیمات']} /> را باز کنید و در بخش **انتقال**
   پروتکل تازه را انتخاب کنید.
2. **اعمال روی همهٔ سرورها** را بزنید تا همهٔ سرورها با هم عوض شوند. اگر سروری تا ۹۰ ثانیه با
   پروتکل تازه وصل نشود، خودش به حالت قبل برمی‌گردد. [SafeSync](../safesync/) را ببینید.

</Steps>

رفتن **به ICMP یا PCK، یا برگشتن از آن‌ها**، فرق دارد، چون این لینک‌ها سرور به سرور ساخته
می‌شوند. پروتکل را روی سرور اصلی عوض کنید و بعد سرورهای دیگر را، هر کدام با کد خودش، دوباره وصل
کنید.
